# Reticulum 1.5.5 feature update and v0.13.0 release implementation plan

**Intent:** Ship LXMF-rs v0.13.0 with the applicable behavior changes from the exact Python Reticulum 1.5.5 tag (`7f2b3b9b524c9386316379af1313b43a5e4f7a5d`).
**Current Behavior:** v0.12.0 is a tested RNS 1.5.2-compatible release with the scoped 1.5.4-dev feature update. Existing Rust interface hot-apply, discovery, and rngit paths do not automatically cover the 1.5.5 changes.
**Expected Outcome:** Changed 1.5.5 features work on existing Rust paths without a blanket claim of inherited Python parity.
**Target-Perspective Output:** Operators can manage supported live interfaces safely; rngit clients receive the new download and work-scope affordances; discovery and local-client behavior retain safe defaults.
**Truth Owner:** The pinned upstream 1.5.5 source defines changed behavior; the repository's existing daemon RPC, interface worker, and rngit service own Rust behavior. `docs/status/current-roadmap.md` and parity matrices own status claims.
**Contract Boundary:** Preserve existing public interfaces and LXMF wire behavior. New CLI/RPC controls must respect configured management policy and report local-start readiness or failure, not merely queue admission or task registration. No unsafe Rust or new crate edge without `tools/scripts/check-boundaries.sh`.
**Cutover:** Extend current interface and rngit paths; no parallel daemon or page service.
**Displaced Path:** None; retain `set_interfaces` for existing callers while new named actions use its established worker where safe.
**Value Density:** Implement only observed 1.5.5 feature changes and affected-path regressions.
**Acceptance Evidence:** Exact-tag Python interoperability for changed wire/page behavior, focused Rust tests, `cargo xtask release-check`, exact-head normal CI, and independently verified v0.13.0 release artifacts.
**Evidence Lane:** Software and hosted CI. Physical devices, client UI, and public-network tests remain outside this release feature gate.
**Kill Criteria:** Do not release if a new feature is merely advertised, management success precedes worker completion, failed reload is reported as success, or 1.5.5 support is claimed from old-pin tests alone.
**Architecture Slice:** `reticulumd` configuration/RPC bridge, `rns-transport` interface lifecycle and discovery, `rns-tools` `rnstatus` and `rngit`, canonical reference manifest/Verify workflow, version/release docs.
**Plan Review Gate:** Requires PRE review before execution.

1. Record the exact upstream delta in `docs/status/rns-1.5.5-delta.md`: named `rnstatus` management; safer discovery auto-connect (Backbone only, verified `RNS` implementation at least 1.5.2, optional unverified override), display filters, and IFAC sanitation; rngit converted Markdown download and work-scope counts; local-client owner/bitrate initialization; interface teardown/policy inheritance; and Link request-receipt `SENT` timeout/rejection. Mark already-covered and not-yet-covered cells explicitly. Keep #608–#614 and #616 separate.
2. On `reticulumd` configuration, `InterfaceHotApplyBridge`, `rns-rpc` mutation route, and `rns-tools` `rnstatus`, add named attach/detach/reload only for the existing hot-apply kinds (`tcp_client`, `tcp_server`, `udp`, `pipe`). Default policy follows Python's enabled management switch but can be disabled by `[reticulum].enable_interface_management`. Attach succeeds after local startup readiness: listener bind for TCP server/UDP, spawned child for pipe, and an active connect/retry worker for TCP client (remote peer connection is not required). Detach succeeds when stop and removal complete. Reload succeeds only after stop and replacement readiness; on replacement failure, attempt to restore the previous working record and return failure with the resulting active/detached state and error. Duplicate/missing/protected/unsupported names, startup failure, and timeout return nonzero CLI status and a structured RPC error or false result; no false success from queueing or task registration. Real local daemon/RPC tests cover the three operations, disabled policy, bind/spawn failure, rollback, and duplicate/missing names. Do not claim the four-kind limit is full Python management parity.
3. On `rns-transport` discovery announce/store/lifecycle and `reticulumd` publish/config paths, retain implementation/version metadata, reject absent/unknown/older implementations for auto-connect by default, limit auto-connect to Backbone, permit the explicit unverified override, ignore empty/`None` IFAC strings, and avoid publishing IFAC without configured credentials. On `rns-tools` `rnstatus`, show stale/unknown discovery rows only with explicit flags. Test safe-default and opt-in decisions, persisted legacy `None` data, and 1.5.5 Python announce decoding; verify the already-correct `.b32.i2p` sample stays correct.
4. On `rns-tools` `rngit_parts/page_media.rs`, `page_git.rs`, and `page_git_work.rs`, add `.md`-only `var_fmt=mu` downloads with a `.mu` filename and link-scoped cleanup, plus Active/Completed/Proposed/All counts over readable workdocs with real `root` files. Existing permission and path checks remain authoritative. Test denied/invalid format, empty and readable scope counts, cleanup, and a pinned-Python Link request for converted bytes/metadata.
5. Audit `rns-transport` local-client startup, interface stop/reconnect, child policy inheritance, default announce cap, and Link request timeout/rejection paths against the Python 1.5.5 fixes. Add focused regressions where Rust has an equivalent hazard; otherwise record why the Rust path already satisfies the behavior or has no equivalent API. A new 1.5.5 feature pin and hosted changed-path checks must not relabel the historical #605/1.5.4-dev contract or the active 1.5.2 baseline as full 1.5.5 parity.
6. Bump coordinated versions to v0.13.0, update changelog/roadmap/matrix/release notes, run `cargo fmt --all -- --check`, focused tests, Clippy, `tools/scripts/check-boundaries.sh`, `cargo xtask release-check`, and `rnx e2e`. Require all normal `.github/workflows/ci.yml` and applicable `verify.yml` checks green on the exact candidate commit before tagging/publishing. Independently verify GitHub assets, checksums, and crates.io packages; report remaining gaps accurately.
