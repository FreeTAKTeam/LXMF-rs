## Completed audit slices

- Post-v0.9.5 link-context fan-out no longer holds the transport-handler lock
  while awaiting link locks and routes through each link's bound interface.
- New `LinkSendReport` APIs expose matched, sent, and failed link counts;
  packet construction and interface dispatch failures are logged.
- Single-destination explicit receipt validation is packet-cache correlated and
  refuses an unrelated known identity's otherwise valid signature.
- Inbound data event delivery and receiver-generated proof dispatch failures are
  observable in diagnostics.
- Packet-ingress workers now stop or cancel their interface when the transport
  receive queue closes; RPC/store reply cancellation and subscriber-free event
  fan-out are handled explicitly with stable diagnostic context.
- Delivery stamp and propagation metadata update failures are logged with the
  message and lifecycle context; receipt-status lookup errors are no longer
  treated as an absent status.
- HTTP event-stream writes return their actual encode/write error, stream
  shutdown failures retain peer/context diagnostics, and RPC listener/writer
  task join failures are observable.
- Legacy message-store upgrades now add columns before dependent indexes,
  backfill required announce fields, and run atomically. Unexpected migration
  and malformed persisted-JSON errors propagate instead of being replaced by
  empty metadata; regressions cover upgrade success and rollback.
- The issue-369 scanner rejects both single-line and multiline ignored channel
  send results, plus mutex-poison branches that previously treated failure as
  absence.
- Core and transport `RnsError` implement standard Rust `Error` and `Display`.
- Core and transport fallible public/private identity and address-hash parsers
  reject malformed, invalid, truncated, and overlong material without panics
  or default cryptographic values; focused constructor regressions cover both
  implementations while typed conversion helpers retain source compatibility.
- LXMF message-ID calculation has a fallible `try_message_id` path. Runtime,
  daemon, embedded, stamp, signing, and verification paths propagate encoding
  failures instead of hashing an empty payload.
- Delivery and propagation policy lookups fail closed on RPC errors, while
  receipt, persistent-store, worker-join, interface shutdown, and process
  cleanup failures retain stable operational context.
- SDK propagation recovery and node-result decoding distinguish missing or
  null fields from malformed values, reject mixed-type arrays, and reject
  numeric overflow instead of defaulting or truncating authoritative state.
- Zero-capacity announce caching is explicitly unbounded and no longer rotates
  on every insertion; a focused regression fixes the edge semantics.
- Receipt validation and link fan-out were split into focused modules; all
  touched regular Rust modules are below 500 lines.
- The shipped ZeroMQ example and SDK documentation use the canonical
  single-endpoint ROUTER/DEALER flow.

## Open code-audit queue

The scanner-backed production inventory now contains zero ignored channel-send
results and zero `if let Ok(...) = mutex.lock()` poison-discard branches. The
closed findings were classified by propagating failures, terminating closed
workers, recording stable context, or using an operation whose semantics do not
fail when all receivers have already stopped.

That zero count proves only the scanner's named failure classes. The scanner
also rejects ignored SQLite execute results after the migration audit.
The production panic/suppression pass also closed malformed identity/hash hex,
invalid Ed25519 key, Fernet IV conversion, LXMF message-ID encoding, announce
cache invariant, spawned-task join, stream flush/write, and interface/process
cleanup paths. Remaining manual review is concentrated in intentionally lossy
compatibility adapters and best-effort reporting helpers; those must stay
explicitly separated from authoritative policy, persistence, and protocol
paths.
