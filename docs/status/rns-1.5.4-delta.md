# RNS 1.5.4 development delta and full-parity acceptance

Assessed: 2026-09-20. Status: **partial; not a full-parity release**.

## Reference and release boundary

The released compatibility baseline remains RNS 1.5.2 at
`ea98db4f53dcf0defc0e71a16e60d28b1229c4e6`. This increment compares it with
upstream development commit `99de23c040d507e3fefca19e87b182302902725d`, whose
`RNS/_version.py` reports 1.5.4. No canonical reference pin, generated inventory
count, SDK parity constant, published version or release tag is promoted here.
The implementation starts from LXMF-rs `533e62547e2c38ad8562bdeffd29c9f8275fffe8`.

A mapped callable inventory is not proof of complete runtime behavior. The
existing 1,857/0/1 inventory must be read with the runtime exclusions in this
file, `reticulum-parity-matrix.md`, and `software-parity-ledger.md`.

## Implemented increment

| Area | Change | Evidence and limit |
| --- | --- | --- |
| RNode BLE lifecycle | Release partial setup on connect, subscription, startup-write and startup-drain errors; preserve the primary error and log cleanup failure; discard stale session state; close before restarting an owned connection. | Fault-injected software backends. Physical adapters were not exercised. |
| Native desktop BLE | Own adapter/peripheral handles before fallible connection work; bound native cleanup by the configured connection timeout; treat native notification-stream EOF as disconnect so the interface reconnects instead of polling empty traffic. | Native feature compilation and mock lifecycle regressions. Windows paired-address discovery is still open. |
| Mobile bearer compatibility | Preserve the separate platform-owned bearer contract in which an empty read means idle; retain idempotent close and cleanup after failed shutdown writes. | Explicit idle-read regression and existing bearer tests. No mobile-device claim. |
| HDLC | Add fallible `Hdlc::frame`, allocating one output buffer and reusing the existing stream encoder. No wire format changes. | Eight vectors generated by the pinned Python `HDLC.frame`: empty, escape bytes, all octets, 500/508-byte payloads, worst-case escaping, and a Backbone-size payload. Existing encode and decode are checked against the same vectors. |
| rngit work transitions | Require repository read/write/interact access; allow only author or document administrator to complete/activate; activate completed or proposed documents; use non-disclosing permission failures; accept Python binary authors and prior Rust hexadecimal authors. | Local service-handler regressions, not an over-Reticulum Git service test. Duplicate target directories fail rather than overwrite existing documents. |
| rngit permission files | Protect executable `.allowed` files from remote overwrite on Unix; retain immediate in-memory refresh after atomic file replacement; append companion suffixes rather than replacing repository extensions. | Local permission and dotted-repository regressions. Executable resolver evaluation is not implemented by this increment. |
| Existing permission-file migration | Reject ambiguous legacy permission-file names and propagate file-read failures instead of silently inheriting broader access. | Fail-closed migration regression. Operator reconciliation is required for ambiguous stores. |

The original tree reproduced five BLE failures and six rngit failures before
implementation. Further regressions guard the mobile idle-read contract and
legacy permission migration. The missing HDLC convenience API initially fails
to compile; this is not evidence that the previous stream encoder was wrong.

## Data migration

Python uses `repo.git.allowed`, `repo.git.work` and `repo.git.releases`. Older
Rust code incorrectly selected `repo.allowed`, `repo.work` and `repo.releases`.
For names without extensions, the paths do not change. For dotted names,
reconcile and migrate existing sidecars node-side before deployment. Do not
blindly rename or auto-fallback: another repository may own the shorter name.
An ambiguous legacy permission file now prevents loading/updating the affected
permission scope; it is not silently ignored. No existing user data is moved
or deleted by this change.

## Acceptance still required for full parity

1. Wire the existing IFAC cryptographic helpers into the daemon's real carrier
   ingress/egress. Authenticated configurations currently fail closed; tests
   must exercise valid/invalid credentials and reject plaintext bypasses.
2. Close the recorded local-client announce timing and parent-interface
   classification differences, with exact retransmission-count and timing
   tests against the same Python reference.
3. Complete executable rngit permission resolvers and configured-access merging,
   remaining work-item operations and Python storage/message schemas, actual
   remote utility workflows, and the 1.5.4 NomadNet media/page service. A local
   bundle or service-handler test does not close a network utility row.
4. Implement or demonstrate equivalent Windows paired BLE address handling.
5. Reassess remaining Resource collision-list regeneration/transfer behavior
   and all existing runtime exclusions with differential tests, rather than
   inferring behavior from public symbol coverage.
6. Run the full pinned-reference interoperability and release acceptance lanes;
   record platform, version, commit, command, failures and intentional
   differences. Promote the canonical pin only after the required software
   rows pass; never change a published tag.
7. Keep hardware evidence separate: paired serial/TCP/BLE radios, device/firmware
   identity, disconnect/reconnect, safe management and transfer captures are
   required for a physical interoperability claim. No RF/HIL run occurred here.
