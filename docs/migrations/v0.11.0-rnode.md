# Migrating to v0.11.0

LXMF-rs `0.11.0` contains the Android/BLE RNode receive and transmit repair.
The LXMF and Reticulum wire formats remain compatible with `0.10.x`.

## Removed startup escape hatch

`reticulum-rs-transport` no longer exposes
`RnodeBleCommandMonitor::accept_degraded_startup`. It allowed callers to enable
payload writes without completing the RNode startup validation contract. Do
not replace it with an unconditional write-enable operation.

Use the normal monitor lifecycle instead:

1. create the monitor and collect startup notifications;
2. call `validate_startup_deadline()` at the configured deadline;
3. stop on a fatal probe, frequency, bandwidth, spreading-factor, coding-rate,
   or radio-state mismatch; and
4. send payloads only after `startup_validated()` is true.

If an otherwise compatible RNode omits only the startup radio-state response,
the runtime records a compatibility warning and validates the remaining probe
and radio parameters before enabling payload writes. This path is not a
general degraded-startup override.

## BLE and queue behavior

Consumers should treat notifications as a byte stream: KISS frames can span
multiple BLE notifications and must be passed to the session without rejecting
partial input. When flow control is enabled, submit the next payload only after
the RNode returns a positive `CMD_READY` response; `READY=0` is a bounded stall,
not permission to drop or duplicate the queued payload.
