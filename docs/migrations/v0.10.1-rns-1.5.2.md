# Migrating to v0.10.1 and RNS 1.5.2

The `0.10.1` maintenance release keeps the RNS 1.5 wire and SDK contracts while
aligning the active Python reference from RNS 1.5.0 to 1.5.2.

## Rust source changes

- Inbound transport queue defaults now match RNS 1.5.2: data `1024`, announce
  `128`, path request `128`, and ingress-limited `8`.
- `reticulum-rs-transport` exports `IfacContext`, optimized/legacy IFAC helper
  entry points, `Profiler`, and `Transport::get_profiling_results` for library
  consumers that own their carrier integration.
- Empty HDLC keepalive frames are consumed before packet admission. Applications
  should not treat these frames as malformed packet errors.
- Shared LocalClient interfaces are not counted by the Backbone dataplane
  ingress/egress limiter; the shared instance remains the admission owner.

## Daemon configuration

The daemon continues to reject `ifac_size`, `network_name`, `networkname`,
`passphrase`, `pass_phrase`, `ifac_netname`, and `ifac_netkey` at startup. The
library IFAC codec is available for a future carrier-specific integration, but
enabling configuration without wiring authentication would be unsafe.

Queue lengths use the RNS names under `[reticulum]`:

```toml
[reticulum]
qlen_in_data = 1024
qlen_in_announce = 128
qlen_in_pr = 128
qlen_in_il = 8
```

Omitting them preserves those defaults. Values must be positive.
